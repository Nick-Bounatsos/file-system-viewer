File System Viewer

File System Viewer scans a directory, records its folders and files, displays file paths and sizes, and provides tools for searching, filtering, paging, sorting, analysing, exporting and restoring the collected data.

Overview

The application is designed to provide a fast overview of large directory trees without having to browse every folder manually.

Scan

Inspect directories

Recursively scans a selected directory, counts accessible folders and records file paths and sizes.

Search

Filter large datasets

Search by text, extension and file size using either the advanced query bar or the visual Filter Builder.

Analyse

Sort and visualise

Sort and page through results, inspect file-size distribution and identify file types consuming the most storage.

Persist

Store and restore results

The latest scan is stored in local MongoDB and a portable CSV Snapshot can be exported and imported without MongoDB Database Tools.

Interface

The main window displays the currently loaded directory, scan metadata, search and filter controls, paged file results and analysis tools.

  • Scan Date shows when the current directory data was collected.
  • Folders / Files shows the total number of accessible folders visited during the scan above the total number of files found.
  • Total Size shows the combined size of all scanned files.
  • Timings breaks the operation into Scan, Process, DB save and Total durations so slow stages can be identified.
  • The main table displays each file's Size and Path.
  • Pagination controls below the table let you move through large result sets without loading every visible row at once.
  • The application opens maximized by default and supports both Light and Dark themes.
Path notation The ~ character represents the root directory that was scanned. This keeps long paths easier to read.
Folder counts from older saved scans Older MongoDB data created before folder counting was added may not contain a folder total. Run Gather Data or Update Data once to populate it.

Gathering Data

Gather Data

Select File → Gather Data… or press Ctrl + G.

Choose a directory. File System Viewer recursively scans that directory and its accessible subdirectories, counting folders and collecting each file's path and size.

The scan runs in a background worker so the interface remains responsive while large directory trees are being processed.

Update Data

Select File → Update Data or press Ctrl + U to scan the currently loaded directory again.

Use this after files or folders have been added, deleted, moved or resized.

Understanding Timings

The Timings card separates the operation into four stages:

Stage What it measures
Scan Traversing folders, discovering files and reading file sizes from the filesystem.
Process Building and formatting the in-memory pandas dataset used by the application.
DB save Saving the newly collected snapshot to the local MongoDB database.
Total End-to-end duration of the complete operation.
What can make a scan slow? Performance depends on the storage device, filesystem, number of files and folders, cloud-synchronised or network locations, and the time needed to persist the final snapshot to MongoDB. The timing breakdown helps identify which stage is responsible.

Searching & Filtering

File System Viewer provides two ways to filter the current dataset: the advanced search bar and the visual Filter Builder. Both use the same search engine and can be combined with sorting, pagination and plots.

Advanced search syntax

Syntax Meaning Example
text Path contains the specified text. invoice
%text% Case-insensitive path search. %invoice%
^text Path starts with the specified text. ^~\Documents
text$ Path ends with the specified text. .xlsx$
!text Exclude paths containing the specified text. !backup
ext:type Match exact file extension, case-insensitively. Multiple extensions can be comma-separated. ext:pdf,xlsx,docx
>size Files larger than the specified size. >100mb
>=size Files greater than or equal to the size. >=1gb
<size Files smaller than the specified size. <500mb
<=size Files smaller than or equal to the size. <=20mb
condition && condition Combine multiple search conditions. ext:pdf && >10mb

Visual Filter Builder

Click Filters ▾ beside the search controls to open the visual Filter Builder. It lets you create the same advanced queries without typing the syntax manually.

  • Text supports Contains, case-insensitive Contains, Starts with, Ends with and Excludes.
  • Extension accepts one or more comma-separated extensions such as pdf, xlsx, docx.
  • Minimum size and Maximum size support Bytes, KB, MB, GB and TB.
  • Apply Filters compiles the selected controls into the advanced query bar and runs the search.
  • Reset clears both the Filter Builder and the active query.
Example generated by the Filter Builder
%invoice% && ext:pdf,xlsx && >=1mb && <=50mb

Size units

File sizes can be written using b, kb, mb, gb or tb.

Search examples

PDF files smaller than 500 MB
ext:pdf && <500mb
Files containing "invoice", regardless of case
%invoice%
Large files excluding backups
>1gb && !backup
Excel files between 5 MB and 100 MB
ext:xlsx && >=5mb && <=100mb
Multiple filters Conditions separated by && are applied sequentially. A file must satisfy all conditions to remain in the result set.

Press Ctrl + F to move focus directly to the search bar.

Press Esc to clear the active search and return to the complete dataset.

Sorting & Pagination

Click the Size or Path column header to sort the current results. Clicking the same column again reverses the sort order.

Sorting applies to the current filtered result set and resets the view to page 1.

Rows per Page

Use View → Rows per Page to select 250, 500, 1,000, 2,000 or All rows.

When a page size is active, the controls below the table provide First, Previous, Next and Last navigation, together with the current page number and visible row range.

Example
Page 2 of 13 · 1,001–2,000 of 12,341
Pagination follows the active result set. A new search, Filter Builder change, sort, scan or imported snapshot resets the view to page 1.

Opening File Locations

Double-click any row in the file table to open that file's parent directory using the operating system's file manager.

The file itself is not opened. File System Viewer opens the directory containing the selected file.

Plots & Analysis

Plot commands are available manually from the File menu. Plot shortcuts were intentionally removed so more analysis views can be added later without consuming keyboard combinations.

Plots always use the current filtered results. If no filter is active, the current result set is the complete dataset. If a search or visual filter is active, only the matching files are analysed.

Plot Size Distribution

Select File → Plot Size Distribution.

The chart groups the current result set into practical file size ranges, making it easy to see whether the selection is dominated by tiny files, medium-sized documents or large media/archive files.

The redesigned chart follows the active application theme, uses clearer labels and grid styling, and displays file counts and proportions for the size buckets.

Plot File Types by Size

Select File → Plot File Types by Size.

This horizontal bar chart ranks file extensions by the total storage space they consume. The largest file types are shown individually and smaller categories are grouped into Other.

The chart also provides file counts, helping distinguish between a file type that consumes space because there are thousands of files and one that consumes space because each file is individually large.

Useful workflow

Filter with ext:pdf,xlsx && >=1mb, then open either plot to analyse only those matching files.

Export & Import

Export

Open File → Export As to choose where the exported file should be saved.

Format Purpose
CSV Snapshot (Backup) Creates a complete, importable backup containing the full dataset and File System Viewer metadata, including folder/file totals and available timing information.
Excel (.xlsx) Exports the complete scanned dataset to an Excel workbook.
HTML (.html) Creates a polished standalone report for the current matching results, with summary cards, Light/Dark mode and built-in row filtering.
CSV (.csv) Exports the current matching results to a semicolon-separated CSV file. This is a normal data export, not an importable backup snapshot.
JSON (.json) Exports the current matching results as JSON.
Text (.txt) Creates a human-readable text listing of the complete scanned dataset.

The application's Exports directory is used as the default location, but the final destination can be chosen in the Save As dialog.

Import CSV Snapshot

Select File → Import CSV Snapshot… or press Ctrl + I.

Choose a file created with CSV Snapshot (Backup). File System Viewer validates the snapshot, loads it into the current session and then attempts to save it as the active MongoDB snapshot.

Snapshot CSV vs normal CSV Only CSV Snapshot (Backup) is designed for import. The regular CSV File export is for external analysis and cannot be restored as an application backup.
Valid snapshot, database save failed If the CSV Snapshot is valid but MongoDB is unavailable, the imported data is still loaded for the current application session. File System Viewer reports the database persistence failure separately instead of incorrectly treating the CSV as invalid.

Requirements

When running File System Viewer directly from Python, the application relies on several Python packages and a local MongoDB server.

Interface

PyQt5

Provides the desktop graphical user interface.

Data

pandas

Handles the in-memory file dataset, filtering, sorting, pagination sources and exports.

Charts

matplotlib + NumPy

Generate the size-distribution and file-type storage analysis plots.

Database

MongoDB + PyMongo

Stores the latest scan locally and reloads it when the application starts.

MongoDB connection

mongodb://127.0.0.1:27017

The application uses a local MongoDB database named fsv.

Additional Python package for Excel export

openpyxl is required when exporting .xlsx files from the Python source version.

MongoDB Database Tools are not required. Backup export/import no longer uses external MongoDB dump or restore commands. Portable backups are handled through File System Viewer CSV Snapshots instead.

Troubleshooting

The application starts without previously saved data

Check that MongoDB is installed and running locally on 127.0.0.1:27017. If MongoDB is unavailable, File System Viewer can still open, but previously saved scan data cannot be loaded automatically.

A CSV Snapshot will not import

Make sure the selected file was created with File → Export As → CSV Snapshot (Backup). A regular CSV export does not contain the snapshot signature and metadata required for restoration.

When parsing fails, File System Viewer reports the actual snapshot error instead of a generic import failure.

The CSV Snapshot imports but cannot be saved to MongoDB

The snapshot itself is valid and remains available in the current session. Check that MongoDB is running locally on 127.0.0.1:27017 before closing the application if you want the imported dataset to persist for the next launch.

Excel export fails

When running from Python, verify that openpyxl is installed.

A directory operation takes a long time

Check the Timings card. A high Scan time points toward filesystem, storage, network or cloud-sync overhead. A high DB save time points toward MongoDB persistence. Process represents in-memory DataFrame construction and formatting.

The folder count is unavailable

Older saved scans may predate folder counting. Run Gather Data or Update Data to generate a current folder total and save it with the snapshot.

Plots contain fewer files than expected

Both plots intentionally analyse only the current filtered result set. Clear the active search/filter if you want to analyse the complete dataset.

Double-clicking a file does not open its directory

The original file or directory may have been moved or deleted since the last scan. Use Update Data to refresh the dataset.
